SESSION FIX — sign-in no longer immediately bounces back to login

What was wrong:
- Login sessions were stored in Cloudflare Workers KV.
- KV is only "eventually consistent" — Cloudflare's own docs say a value
  you just wrote is not guaranteed to be readable again for up to 60
  seconds, even from the same location.
- The app writes the session, then immediately redirects to "/" and
  checks that same session. That immediate re-read is exactly the case
  KV isn't built for, so it looked like you were signed out again right
  after signing in.

What changed (src/index.js):
- Sessions now live in D1 (a real SQL database, already used elsewhere
  in this project) instead of KV. D1 gives a read-after-write guarantee,
  so a session is valid the instant it's created.
- A new "sessions" table is created automatically on first request
  (also included as migration-sessions.sql if you want to run it by hand).
- Added the missing POST /api/auth/logout route (the sign-out
  confirmation page was already calling it, but it didn't exist, so
  clicking "Sign out" there never actually cleared your session).
- The plain /logout link and Google sign-in now also properly delete the
  D1 session row on logout / create it via the same helper.

Workers KV is still used for Google Drive tokens and OAuth state, since
those aren't read back milliseconds after being written.

Deploy/upload:
1. Replace your GitHub project files with this ZIP's contents.
2. Deploy the Worker again (wrangler deploy).
3. No manual DB migration is required — the sessions table is created
   automatically. migration-sessions.sql is provided if you prefer to
   run it yourself.
